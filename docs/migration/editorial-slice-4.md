# Slice 4 editorial presentation — local visual review

The website remains Astro 7.3.8 static output on the installed Node 24.21.0/npm 11.19.0 toolchain. No dependencies, fonts, external graphics or runtime services were added. Run the existing `npm run build`, `npm test` and explicit `npm run review:build`; the new presentation tests invoke the isolated review command themselves so validation-only CI also exercises component rendering on a fresh checkout. Tests create no public preview or uploaded artifact.

## Presentation architecture

`src/styles/tokens.css` owns the local candidate palette, system font roles, fluid type sizes, spacing, widths, borders/radii, motion and flavor accent hook. These are review choices, not newly approved canonical brand facts. Georgia/system serif and system sans-serif need no downloads. Native query boundaries are 48rem, 72rem and 96rem, declared centrally in the token file and used literally in global.css because native CSS custom properties cannot drive media queries.

`SiteLayout` consumes the existing validated site metadata and composes `SiteHeader` and `SiteFooter`. Both use one presentation navigation list. Four visible links wrap into a two-column mobile grid without a disclosure control, duplicate hidden menu or JavaScript. Exact current routes have aria-current=page; detail routes identify their Flavors navigation location. Footer navigation has a distinct accessible label.

`EditorialHero` composes one h1, plain description, optional actions and an optional decorative/visual slot. `SectionHeading` and `EditorialSection` support exactly the text-only, split and feature-band compositions. `DecorativeBackground` renders static CSS arcs/surfaces hidden from assistive technologies; it is neither artwork nor a logo/mascot surrogate.

`FlavorCollection`, `FlavorCard`, `FlavorDetail`, `MediaFrame` and `FlavorStory` are pure presentation of validated mapper props. Presentation types derive from that mapper; no second content schema/record source exists. Media uses the exact delivered src and alt, with contain sizing and no crops, filters, overlays, conversion or optimization. No intrinsic dimensions are fabricated from missing projection data. The optional editorial section has the structural heading Trancy’s Worlds and renders supplied title/paragraphs only; without an editorial reference the complete section is omitted. It is never a top-level navigation destination.

`EmptyCollectionState` and `ContactPanel` retain neutral development placeholders. Home/About use only the established name, route labels and existing pending-copy notices; no launch, availability, product, company-history or manufacturing statements are added. The sourced creative principle remains direction for review and is not treated as approved public copy. No Trancy, package, logo, stock image, email, telephone, social profile or contact form is rendered. Contact channel/copy approval remains a later prerequisite, not a fallback data source.

## Responsive and accessibility provisions

Mobile is the default single-column reading order; tablet adds bounded grids, desktop widens gaps, and wide layouts retain a maximum reading/container width. Zero-minimum grid tracks, wrapping navigation/text and fluid sizes support small widths/enlarged text. Global horizontal clipping does not conceal overflow; clipping is limited to inaccessible decoration. No CSS order/dense-grid reordering, sticky/fixed navigation or animation gate is used.

Landmarks, one h1, subordinate headings, working skip target, native links, visible focus, at least 44px-equivalent navigation targets and labelled nav/sections are retained. Focus colors switch on reading surfaces. Deterministic token contrast tests cover actual text pairs at >=4.5:1 and focus pairs at >=3:1. Decorations are aria-hidden, approved media alt is preserved, and reduced-motion removes transitions/animations. These checks do not prove full accessibility conformance or actual browser reflow.

## Boundaries and review

All Slice 3 schemas, pins, eligibility/recipe rules, release inputs, media inventory, fixture assumptions and CI policy remain unchanged. Normal public-astro is empty and normal output still has five HTML routes. Only explicit review output under .review-build renders fictional test cards/details. New CSS is generated by Astro, not placed in the public asset root.

Visual, keyboard/touch, screen-reader, 320px/tablet/desktop/wide, enlarged text, device/font variation and reduced-motion checks require human review of the new design. A pre-slice browser confirmation does not approve these changes. Automated rendering/contrast tests are bounded structural evidence, not manual acceptance, production content approval or Slice 5 auditing. No external progression follows from test success.

# Slice 3 local public inputs

Normal `npm run dev` and `npm run build` validate fixed website-owned `content/` inputs. No environment variable selects another content root. The Change 007 release is empty, so there are no Flavor cards, detail routes or media. Missing empty flavors/editorial/public directories are allowed for a fresh checkout; any supplied record or public file is checked. An empty release may omit eligibility.json and its pin. A supplied snapshot is validated, including its media digest and any supplied release pin.

`schemas/publication` preserves the Studio v1 common and projection bytes unchanged. `schemas/origin.json` records source paths, revision and SHA-256 digests. The mapper resolves schemas locally and verifies those pins. `closed-json.mjs` is a bounded JSON parser and evaluator for the assertion keywords used by these snapshots and the website schemas, not a general JSON Schema implementation. It rejects duplicate keys, invalid UTF-8, lone surrogates, nonfinite/unsafe numbers, oversized or excessively nested JSON; it never follows network schema references.

Website-owned closed v1 roots are site, editorial, eligibility, media and release-set (see their schemas). Site metadata is development-only. Editorial is plain paragraphs with an optional title, keyed to an exact Flavor; omission of the member editorial reference omits the story. The unchanged Studio projection still requires alt, canonicalArtwork and artwork. Local validation joins exact Flavor/source/derivative identities, recipe/version/parameters, deliveryRef, scope and recorded validity, with exact-byte SHA-256 pins for snapshot/media/projection/editorial/delivery. Only included members populate views. Unlisted malformed inputs fail; unlisted records grant no routes or assets.

No real recipe profile is registered. A real projection cannot become eligible by supplying arbitrary safe recipe parameters. A future profile requires source-specific human review of transformation semantics, dimensions, tool/version, creative scope, color/transparency, metadata/privacy, decoded result and exact output evidence. The only parameter schema currently supported is the test-only fixture-placeholder version 1 closed empty object.

All files Astro could copy from public-astro are inventoried against selected deliveries before rendering. Delivery paths are restricted to public-astro/assets, must be regular files with verified bytes, and cannot traverse symlinks or use private/original/legacy/remote paths. There is no copying from Studio or original artwork. Existing shared brand/Trancy assets have no admission interface in this slice. Normal output is bounded to the five neutral foundation routes and generated CSS, with no client scripts, media or fixture content.

`npm run review:build` is the explicit internal fixture command. It uses only tests/fixtures/public-inputs and its assets child, never dist. Output is fixed to .review-build with noindex and INTERNAL SYNTHETIC TEST ONLY notices. Its separate fixture-eligibility-assumptions envelope provides fictional upstream assumptions, not Studio approvals. The test-only release pin's revision is the assumption contractVersion (1); the envelope has no fabricated review revision/timestamp/reviewer. This harness convention does not change the normal SnapshotRef joining rule. Normal kind/identity/path/marker/digest checks reject those inputs, including relabelled known placeholder bytes. No environment or command output option can promote them into normal builds.

`npm test` includes schema/identity/path/leakage negatives and website-only isolated repeated normal/review builds, with content network primitives blocked and credentials absent. Dependencies are reused from the existing locked local installation; no dependencies or authority records are installed/created. Validation-only CI already runs npm run build followed by npm test; no workflow/deployment permissions are added. Local results do not establish remote Linux CI, complete Slice 5 auditing or publication readiness.

The eligibility snapshot is a reviewed public-safe result, not rights proof, authentication, publication approval or a live revocation feed. Private authority/reviewer/approval/evidence/publication records remain in Studio. No expiry or current build time is invented. Recorded invalid states fail locally, but unseen upstream changes cannot be detected offline. Authorized source-use/creative and website/content reviewers must retain private bindings and revalidate current eligibility before PR authorization and final publication. The owner approves the exact candidate and review evidence; the maintainer/release owner confirms current validity. Withdrawal requires separately authorized removal/replacement and hosted/cache verification. Structural PASS leaves real publication readiness BLOCKED/UNVERIFIED.
